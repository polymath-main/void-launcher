# VoidLauncher config schema (generated)

> Generated by `scripts/generate-schema-doc.py` from
> `model/LauncherConfig.kt` + the serializer in `core/ConfigManager.kt`.
> Do not hand-edit the tables — regenerate after changing a field;
> `SchemaDocTest` fails if a field is added without a doc row.

Store file: `<external-files>/config/config.json` (`VoidPaths.CONFIG`).
Load: 4-tier (store → internal → bundled asset → Kotlin defaults),
lenient per-field fallback; unknown keys are warned about, never a
whole-file rejection. `schema_version` is advisory (current 1).
Export writes the CURRENT config, never defaults (1.1.0 fix).
Settings SAVE TO STORE saves to the store; EXPORT FILE… is the SAF
picker export. A config file can reveal directory paths and package
names — share carefully (the export toast says so too).
